# quench-android
Native code for the Android host: a framed-stdio protocol, an operation registry and built-in operations.

## What it is
`quench-android` is the Rust side of the Android host's `native` plugin. An app's native code is a separate program: the Kotlin host starts it, writes one request to its standard input and reads one answer from its standard output. The crate provides the frame format, an operation registry and the built-in operations `core.version`, `core.echo` and `tz.next`. It has no `unsafe`, no JNI and no loaded library.

It builds on `quench-core` (`Date`, `Time`), `quench-serde` (JSON) and `quench-tz` (zone resolution). The Kotlin half of the host is generated by `quench android init` and `quench plugin add` from `quench-tool`.

## Use cases
- Run Rust logic from a Kotlin Android app by registering named operations.
- Implement background jobs as operations named `job.<task>` for the `jobs` plugin.
- Compute the next local time in a zone with `tz.next`.
- Test operation handlers without a device by serving in-memory streams.

## Example
```rust
// native/src/main.rs
fn register_ops() {
    quench_android::register("greet", |input| {
        let name = std::str::from_utf8(input).map_err(|e| e.to_string())?;
        Ok(format!("hello, {name}").into_bytes())
    });
}

fn main() -> std::process::ExitCode {
    quench_android::run(register_ops)
}
```

Standard output belongs to the protocol; log with `eprintln!`. From Kotlin the generated `Native` object calls it:

```kotlin
val bytes = Native.invoke(context, "greet", "Ada".toByteArray(), timeoutSeconds = 60)
```
