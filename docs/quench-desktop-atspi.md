# Quench Desktop AT-SPI

`quench-desktop-atspi` (crate `quench_desktop_atspi`) makes a native-rendered window readable by a screen reader on Linux. Orca and the other assistive technologies talk to applications over a second D-Bus, the **accessibility bus**; this crate has **the D-Bus wire protocol written by hand** (no `dbus` crate, no `libdbus`) and the AT-SPI objects on top of it.

- `value`, `message`, `conn`: the types and their alignment rules (all of `y b n q i u x t d s o g a () {} v`), messages with their header fields, the EXTERNAL authentication (the user id read from `/proc/self`, so no `unsafe`; the authentication lines are read a byte at a time, because what follows `BEGIN` is the first message and must not be lost in a buffer), connecting to `unix:path=` and `unix:abstract=` addresses, serial numbers, calls and replies. Little-endian only. Hostile input is an error, never a panic: lengths, nesting and padding are bounded and tested.
- `Service::start(name)` asks the session bus for the accessibility bus's address (`org.a11y.Bus.GetAddress`; the environment's session address, else `/run/user/<uid>/bus`), connects to it, registers the application with the registry (`Socket.Embed`) and answers calls from a thread of its own. Everything it answers comes from a **snapshot** of the [`AccessNode`](./quench-ui-native.md#accessibility) tree: `Service::publish(tree)` replaces it (and sends `StateChanged` signals when focus moves), `take_actions()` returns what a screen reader asked the program to do (click, focus, scroll into view) for the program's own thread to carry out.
- The objects: an `Application` (role 75) with one `Frame` (the window) whose child is the page (`Document`, the tree under it). Each answers `Accessible` (name, description, role and role name, state set, attributes, children, parent, index, interfaces) and the `Properties` interface; the window and nodes `Component` (extents, position, size, contains, the node at a point, grab focus, scroll to); nodes with actions `Action` (`click`, `focus`); text fields and text `Text` (text, character count, caret, selection). Role and state numbers are those of `AtspiRole` and `AtspiStateType` (checked against the library on the machine).

Verified against a **real AT-SPI client** (the Python `Atspi` library Orca is built on): the gallery window's tree is listed with roles, names and screen positions, `grab_focus` moves focus into a field, and `do_action` on a button clicks it (opening the gallery's dialog). The unit tests play both ends over socket pairs and fake buses.

**Value and EditableText.** Sliders and progress bars (`Role::Slider`, `Role::ProgressBar`) have the `Value` interface (`MinimumValue`, `MaximumValue`, `CurrentValue`, `MinimumIncrement`; read only). Text boxes that are not read only or disabled have `EditableText`: `SetTextContents`, `InsertText` and `DeleteText` are queued as whole new texts (`take_edits()`), which the window host applies with `NativeRenderer::set_field_value` (focus, the text replaced, an `Input` event); `CopyText`, `CutText` and `PasteText` answer false (the clipboard is the window's).

**Signals.** Each publish is compared with the one before, and the service sends `PropertyChange` (`accessible-name`), `ChildrenChanged` (`add` and `remove`, with the child's reference), `TextChanged` (`insert` and `delete` with the offset, length and text, found as the changed middle of the old and new text), `TextCaretMoved`, and `StateChanged` for `checked`, `expanded` and `selected`, besides the `focused` ones.

Not done: text attributes and per-word extents, a writable `Value`, relations (labels are folded into names), keyboard events from the registry, and any test with Orca itself.
