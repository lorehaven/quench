`quench_ui_web::bridge` (`src/bridge.rs`): calls to the native plugins of the host app (Android; the Linux desktop host) and the events they push. The wire protocol is in [Internals](internals.md#the-host-bridge); typed clients are generated by [`#[plugin]`](../quench-ui-web-macros/index.md) and listed in [API: plugins](api-plugins.md).

## `BridgeError`

```rust
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct BridgeError {
    pub code: String,
    pub message: String,
}

impl BridgeError {
    #[must_use]
    pub fn new(code: &str, message: &str) -> Self;
}
impl fmt::Display for BridgeError   // "{code}: {message}"
impl std::error::Error for BridgeError
```

Re-exported as `quench_ui_web::BridgeError`. `code` is one of a small set the application can act on:

| code | When |
|---|---|
| `unavailable` | no host (plain browser), the host did not connect within 3 s, or the fetch failed (`FetchError::Network`); `message` is the reason |
| `aborted` | the fetch was aborted (`FetchError::Aborted`), message `the call was dropped` |
| `unknown_plugin`, `unknown_method`, `invalid_args`, `permission_denied`, `internal` | sent by the host in `err.code` |
| `bad_response` | the answer was not JSON, had neither `ok` nor `err`, or `ok` is not a `T` |
| anything else | a code the plugin chose |

If the host's `err` has no `code` the code is `internal`; a missing `message` is the empty string. (`unknown_plugin` etc. are produced by the host, not by this crate.)

## `call`

```rust
#[allow(clippy::future_not_send)]
pub async fn call<A: Serialize, T: Deserialize>(
    plugin: &str,
    method: &str,
    args: &A,
) -> Result<T, BridgeError>
```

`Serialize`/`Deserialize` are the `quench_serde` traits. Sends the envelope `{"id": <n>, "plugin": plugin, "method": method, "args": args}` as the body of a `POST quench-bridge:call` request and reads the answer. `args` should serialise to a JSON object (by parameter name). `id` is a thread-local counter starting at 0 that wraps at `u32::MAX`. `T` is read from the answer's `ok` value (re-parsed from its JSON text); use `()` for `null`. Dropping the future forgets the call; a late answer is ignored. This is what the methods generated by `#[plugin]` call.

Errors: see `BridgeError`. Order of checks: transport failure, then JSON parse of the answer, then `err`, then missing `ok`, then the `T` conversion.

## `on_event`

```rust
pub fn on_event(listener: impl Fn(&str, &str, Value) + 'static)
```

`Value` is `quench_serde::Value`. Registers `listener(plugin, event, data)` for every event the host pushes from now on. Listeners are never removed and all see every event. The first registration spawns a task that opens `EventSource::open("quench-bridge:events", &["event"])` and delivers each message; later calls only add listeners. A message that is not JSON, or has no string `event` field, is ignored; `plugin` defaults to `""` and `data` to `Null`. Listeners are cloned out before being called, so a listener may add listeners or make calls. Events sent while no page is connected, or before the source opens, are lost. If the event stream ever closes, the task ends and is not restarted.

## `reset`

```rust
#[cfg(not(target_arch = "wasm32"))]
pub fn reset()
```

Resets the call counter and drops the listeners; for tests (`mock::reset` calls it).

## Example

```rust
use quench_ui_web::{BridgeError, bridge};

#[quench_ui_web::plugin("echo")]
pub trait Echo {
    async fn say(text: String) -> Result<String, BridgeError>;
}

bridge::on_event(|plugin, event, data| { /* e.g. ("files", "progress", {...}) */ });

match Echo::say("hi".into()).await {
    Ok(text) => { /* ... */ }
    Err(e) if e.code == "permission_denied" => { /* ask the person to allow it */ }
    Err(e) => { /* e.message */ }
}
```
