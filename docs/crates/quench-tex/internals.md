## The reader

`parse` is three steps over the source string: the lexer (`src/lexer.rs`) turns it into tokens with byte offsets, the parser (`src/parse.rs`) reads the tokens into a `Formula`, expanding user macros on the way, and the symbol tables (`src/symbols.rs`) answer what each command stands for.

* **Tokens**: `Char`, `Command` (the name without backslash), `Begin` `{`, `End` `}`, `Sup` `^`, `Sub` `_`, `Align` `&`, `Param(1..=9)` (`#1`…`#9`), `Shift` `$`, `Tie` `~`, `Space`. Comments (`%` to the end of the line) are dropped, runs of white space are one `Space`, spaces after a control word are dropped. `#` not followed by a digit 1-9 is a `Char('#')`, so it can appear in a colour (`#ff0000`); `#1` is a parameter token; a colour argument (`\color`, `\textcolor`) turns a parameter token back into `#` and the digit, so `#1a2b3c` reads as written (in a macro body the substitution has already happened).
* **Parsing** is a recursive descent over TeX's math lists. A list is read until a token that ends it (`}`, `&`, `\\` or `\cr`, `\end`, `\right`, `\middle`, a `$`, a `]` when reading a `\sqrt` degree, or the end), and the construct that asked for the list decides whether that end is right where it is: a `&` ends a cell in an array and is a syntax error anywhere else. A command is tried, in order, as a construct (fractions, accents, `\sqrt`, braces, stacks, `\begin`, `\not`, `\operatorname`, `\left`), a font, text, class or colour command, a spacing command, a `\big` delimiter, a symbol, a large operator, a named operator; failing all of those it is `Error::Unsupported`. Style, old-style font (`\rm`) and `\color` switches take the rest of the current list as their body.
* **No partial results**: the first error stops the whole formula. There is no recovery; the caller shows the source.
* **Depth**: every list and atom entered counts towards a depth limit of 150; deeper is ``the formula is nested too deeply``, never a stack overflow. 70 nested groups, 40 nested radicals, 30 nested fractions, 40 nested superscripts and 40 nested `\left(` parse and render (tested).
* **Arguments** are one token or a braced group, as in TeX: `\frac12`, `x^\alpha`. A command's argument is parsed as an atom, so `\frac\alpha2` works.

## Macros

`Macros` maps a name to a `Macro { params, default, body }` (the type is crate-private), where `body` is a token list with `Param` tokens. When the parser peeks at a command that is defined as a macro, it expands it: reads the arguments unexpanded (one token or a braced group each; an optional first argument in `[…]` for a definition with a default), substitutes them for `#n` (the body's tokens take the call's offset, the arguments keep theirs) and pushes the result in front of the remaining tokens, so reading goes on from the start of the expansion, as TeX's does. User macros are looked up before built-in commands, so they shadow them.

Limits: 10 000 expansions per formula (``macro expansion too deep (is `\a` defined in terms of itself?)``) and 100 000 tokens waiting to be read (``macro expansion too large (in `\a`)``, for a definition that doubles itself). Both are syntax errors, so a recursive definition cannot hang or exhaust memory.

`parse_with` parses against a clone of the caller's `Macros` and stores the clone back only on success, which gives the "a formula that fails changes nothing" guarantee.

## Text output

`to_unicode` and `to_text_block` are the same walk over the tree (`src/text.rs`). Each node becomes an item: a block of lines with a baseline row and the TeX class it has for spacing. A list is its items side by side on their baselines.

* **Classes and spacing**: binary operators with nothing to operate on become ordinary (TeX's rules 5 and 6, the same test as the typesetter). Between neighbours, TeX's medium and thick spaces (around binary operators and relations) are one cell, and so is the thin space after punctuation; other thin spaces are one cell only next to an operator (after `∑` with scripts, around named operators: `2 cos θ`, `sin x`). Inside scripts the spaces that TeX drops in script style are dropped (`xⁿ⁺¹`, not `xⁿ ⁺ ¹`). Explicit spaces: a space of `e` ems is `round(2e)` cells, at least 1 for any positive space (`\,` is 1, `\quad` 2, `\qquad` 4); negative spaces are nothing.
* **Characters**: alphabets through `math_alphanumeric`; the dot operator U+22C5 (`\cdot`) is written as the middle dot U+00B7, which more terminal fonts have. Letters stay upright (there is no italic in the text output). Colours are ignored; `\displaystyle` puts limits above and below in a block, `\scriptstyle` drops the spaces around binary operators and relations.
* **Inline** (`to_unicode`): everything is one line. Fractions are `num/den`, with a side parenthesised when it is more than one term (`(a + b)/2`, `1/(x + 1)`, `2x/3`), and the whole fraction parenthesised when an atom touches it (`(1/2)x`) or when it is itself a side (`(a/b)/c`). Binomials are `(n k)`. Scripts use Unicode super- and subscript forms when every character has one (`x²`, `aᵢⱼ`, `xⁿ⁺¹`, `e⁻ˣ`, `xₘₐₓ`), else `^x`/`_x` for one character (`x^*`, `∮_C`) and `^(…)`/`_(…)` for more (`e^(iπ)`, `lim_(x→0)`). A base that is more than one atom gets parentheses (`(a + b)²`). Radicals are `√x`, `√12`, `√(x + 1)`, `∛x`, `∜x`, `ⁿ√x`. Accents are combining characters after each base character (`x̂`, `A̅B̅`); braces keep only their label as a script; arrays are rows joined by `; ` with cells joined by a space (`, ` in `cases`), inside the environment's delimiters, and a one-sided `cases` brace is closed (`{x, x ≥ 0; −x, otherwise}`).
* **Block** (`to_text_block`): fractions stack over a rule of `─`; a script stays inline when it is at most two cells and every character has a Unicode form (`x²`, `aᵢⱼ`, `x⁻¹`), otherwise it is raised or lowered a row; limits go above and below operators in display style (`∑`, `lim`), integrals keep theirs beside. `∑` and `∏` are a single character with limits above and below (a three-line `⎲`/`⎳` reads worse in most terminal fonts); a radical is `√` with a row of `_` over the radicand, and a tall radicand gets a `│` stem. Delimiters grow from Unicode's bracket pieces (`⎛ ⎜ ⎝`, `⎡ ⎢ ⎣`, `⎧ ⎨ ⎩ ⎪`, `│`, `‖`); a two-row `cases` brace is `⎰ ⎱`. Over- and under-braces are drawn with `╭ ─ ┴ ╮` and `╰ ─ ┬ ╯`. Arrays align their columns, with two cells between matrix columns, `│` and `─`/`┼` for rules. The common indent is removed and trailing spaces trimmed; **the caller centres the block**.

## The typesetter

`typeset` (`src/typeset/`) turns the same tree into a box (`Bx`: width, height above the baseline, depth below it, italic correction, and the items drawn in it) by the rules of *The TeXbook*, Appendix G, with the font's `MathConstants` in place of TeX's font parameters (`σ`/`ξ`), the way the OpenType MATH specification and MathML Core restate them. All lengths are font units of the math font at text size; a constant at a script size is multiplied by the style's scale.

* **Styles**: D, T, S, SS and their cramped forms. Superscripts go D/T → S, S/SS → SS; subscripts the same, cramped; numerators D → T, T → S, else SS; denominators the same, cramped; radicands and accent bases cramped. Script sizes are `script_percent_scale_down` and `script_script_percent_scale_down` (60 % and 50 % in Noto Sans Math; 70 % and 50 % when a font gives 0).
* **Letters** are set in math italic: Latin letters map to U+1D434… (h to U+210E), lowercase Greek to U+1D6FC…, and `∂ ϵ ϑ ϰ ϕ ϱ ϖ` to their italic forms; capital Greek stays upright (TeX's convention) unless `\mathit`. `\mathrm` keeps the plain letter, `\boldsymbol` uses bold italic (Latin and Greek) then bold, other alphabets `math_alphanumeric`. When the font lacks the mapped character the plain one is tried, then `MissingGlyph`.
* **Spacing** between atoms is TeX's table of chapter 18 (thin 3 mu, medium 4 mu, thick 5 mu; the medium and thick spaces and some thin ones only in D and T), after rules 5 and 6 have turned binary operators with nothing to operate on into ordinary atoms. 18 mu make an em at the current size. A `\middle` is a closing delimiter to what is before it and an opening one to what follows. Each atom's italic correction is added to its advance.

### Appendix G: what is followed and what is approximated

Laid out by the full rules, each with the font's constants:

* **Rule 15, fractions**: numerator and denominator shifts (`fraction_numerator_shift_up`, `…_display_style_shift_up`, denominator likewise) raised or lowered further to keep the minimum gaps to the rule (`fraction_numerator_gap_min`, display variants), the rule of `fraction_rule_thickness` centred on the axis. `\binom`-like stacks without a rule: `stack_top_shift_up`, `stack_bottom_shift_down` and `stack_gap_min` (display variants), the shortfall split evenly between the two. Then the delimiters around a `\binom` grown by rule 19.
* **Rule 11, radicals**: the radicand cramped; the sign grown (variants, then assembly) to cover radicand height, depth, the gap (`radical_vertical_gap`, display variant) and `radical_rule_thickness`; extra size of the sign split into the gap as TeX does; the overbar on top; `radical_extra_ascender` above. A degree in scriptscript style, raised to `radical_degree_bottom_raise_percent` of the sign's height, with `radical_kern_before_degree` and `radical_kern_after_degree` (negative: the sign moves back under the degree).
* **Rule 18, scripts**: a character base places its scripts by the constants alone (TeX's u = v = 0 for a character box), any other base hangs them from its top and bottom (`superscript_baseline_drop_max`, `subscript_baseline_drop_min`); `superscript_shift_up` (or `…_cramped`), `superscript_bottom_min`, `subscript_shift_down`, `subscript_top_max`; with both scripts, the gap `sub_superscript_gap_min` restored by raising the superscript up to `superscript_bottom_max_with_subscript` and lowering the subscript for the rest; the superscript placed after the italic correction, a large operator's subscript moved left by its italic correction; `space_after_script` after the scripts. A delimiter character typed as a base is a character to these rules, even though the font calls it an extended shape (TeX looks at the nucleus, not the glyph); a large operator is a box.
* **Rule 13, large operators**: in display style the first vertical variant at least `display_operator_min_height` tall (or the largest), centred on the axis. Limits (rule 13a) centred above and below with `upper_limit_gap_min`/`upper_limit_baseline_rise_min` and `lower_limit_gap_min`/`lower_limit_baseline_drop_min`, the upper limit shifted right and the lower left by half the italic correction. `Limits::Display` operators and `\mathop{…}` take limits in display style only; `\limits` (`Always`) and `\nolimits` (`Never`) override that for both. `\overset`, `\underset` and `\stackrel` use the same limits layout.
* **Rule 19, `\left`/`\right`**: the delimiters cover at least `\delimiterfactor` = 901/1000 of twice the larger extent of the content from the axis, or fall short of it by at most `\delimitershortfall` = 0.5 em (5 pt at 10 pt); grown from variants, then the assembly, centred on the axis. `\middle` delimiters get the same size. An empty delimiter (`.`) is `\nulldelimiterspace` = 0.12 em. Matrix delimiters use the same rule.
* **Over- and underlines** (rules 9, 10): `overbar_vertical_gap`, `overbar_rule_thickness`, `overbar_extra_ascender` over a cramped base; `underbar_vertical_gap`, `underbar_rule_thickness`, `underbar_extra_descender` under it.
* **Braces**: the brace grown horizontally to cover the body, `stretch_stack_gap_below_min` between body and an over-brace (measured to the brace's ink), `stretch_stack_gap_above_min` between brace and label (and the mirror for under-braces). The label is in script style; the whole is an operator atom.

Approximated or simplified (read from the code; not stated in the README):

* **Math kerns are not used.** The script rules use italic corrections only; `MathKernInfo` (cut-ins at the corners) is never consulted. Noto Sans Math has no math kerns, so nothing changes with the bundled font; with another font, scripts on letters like `f` or `P` are spaced as without kerns.
* **Primes** are set at the size of their base, not in script style, without the superscript shift: the font draws its prime glyphs raised already. A superscript after primes follows them in the superscript's place. Primes and limits: a base with primes always gets its scripts beside.
* **Accents** (rule 12): the accent is centred on the base's top accent attachment (or, for a compound base or a glyph without one, at (width + italic correction) / 2 of the base) over the accent's own attachment (or the middle of its ink), and raised by `max(0, base height − accent_base_height)`, which is MathML Core's reading. TeX's skew and `\fontdimen` x-height are not used, and `flattened_accent_base_height` (flattened accent forms for tall bases) is not used. A wide accent (`\widehat`) takes the widest variant no wider than the base (the narrowest if none is), the assembly only past the widest variant; a wide arrow takes the narrowest variant that covers the base, else the assembly.
* **`\big` sizes** are `0.901 × {1.2, 1.8, 2.4, 3.0} em`, grown like a `\left` delimiter to that size, not TeX's fixed font sizes.
* **Constants not used**: `math_leading`, `delimited_sub_formula_min_height`, `flattened_accent_base_height`, `stretch_stack_top_shift_up`, `stretch_stack_bottom_shift_down`, `skewed_fraction_horizontal_gap`, `skewed_fraction_vertical_gap`. There are no skewed fractions and no continued fractions (`\cfrac` is `\dfrac`).
* **No script-style glyphs**: scripts are the text-size glyphs scaled; the `ssty` feature of `GSUB` is not read. No cut-in kerning, no `\mathsurround`, no line breaking of a long formula, no `\displaystyle` alignment of equation numbers.
* **Named operators** are the math font's upright letters; a space in the name (`lim sup`) is a thin space (3 mu).
* **Text**: `\text` is set in Noto Sans (bold for `\textbf`) at the size of the style, with GPOS pair kerning, spaces not drawn; `\textit` is Noto Sans slanted by 0.2 (`Face::TextItalic`: no italic face is embedded); `\textsf` is Noto Sans like `\text`; `\texttt` takes ASCII letters and digits from the math font's monospace alphabet and the rest from Noto Sans. A character Noto Sans lacks is looked up in the math font, then `MissingGlyph`. Math inside text is set in text style when the text is in display style.
* **A group of one ordinary character** is that character (`{x}^2` places the script as for `x^2`); `\mathbb{R}` of one character likewise.
* **Arrays** use LaTeX's lengths at 10 pt (1 pt = 0.1 em): `\arraycolsep` 5 pt on each side of a column boundary in `matrix` and `array` (and at the outer edges of `array` only), a quad between the columns of `cases` and `gathered`, nothing inside an `aligned` column pair and 2 em between pairs, 5/18 em in `smallmatrix`. Rules are 0.04 em (0.4 pt), double rules 0.2 em apart. Rows with struts of height 0.84 em and depth 0.36 em (times 1.2, `\arraystretch`, in `cases`); `aligned` and `gathered` rows (in display style) 1.5 em apart baseline to baseline (12 pt `\baselineskip` plus 3 pt `\jot`), or the rows' extents plus 0.4 em when they would come closer than 0.3 em. Cells in text style (display in `aligned`/`gathered`, script in `smallmatrix`). In `aligned`, a cell after `&` starts with an empty group so a relation there is spaced as if something came first. The array is centred on the axis.

The geometry tests check these rules on the bundled font within half a font unit: the fraction rule on the axis with the font's thickness, gaps around a tall numerator, script shifts and scales, sub/superscript gaps, the display sum's variant and limits, integral script offsets, delimiter cover, radical gap and degree, class spacing, accent attachment, matrix alignment, `\big` sizes, braces, bars, alphabets, text fonts, colours, and that every reference formula's ink stays inside its box.

## Growing glyphs

A delimiter, radical sign or wide accent is grown from the font's `MathVariants` (`src/typeset/boxes.rs`):

* **Vertically** to a size (height plus depth): the first variant whose `advance` (scaled to the style) reaches it; else the assembly built to that size; else the largest variant. The box is where the font puts it, then centred on the axis by the caller.
* **Horizontally** to a width, with or without `cover` (braces and arrows cover; wide accents choose as TeX's rule 12 does, see above).
* **Assembly**: the parts with every extender repeated `n` times, `n` from 0 up (at most 1000), until the length with the least overlaps reaches the target. For each joint, the least overlap is `min(min_connector_overlap, most)` and the most is the smaller of the left part's end connector and the right part's start connector, **clamped to both parts' full advances**. The clamp matters for Noto Sans Math, whose `→` shaft has an end connector (777) longer than the shaft (658). The slack is spread evenly over the joints (one factor λ in 0..1 for all), so the assembly is the target length or just past it. Vertical parts go bottom to top from the baseline, horizontal ones left to right; the assembly's italic correction is the font's `GlyphAssembly::italics_correction`. An assembly without any extender of non-zero length is used as it is.

## Drawing

* **RGBA and PNG** (`src/typeset/draw.rs`): the pixel area is the union of the box and the ink (`Typeset::ink`), scaled by `pixels_per_em / units_per_em`, rounded outwards to whole pixels, plus `padding` on each side, at least 1×1. Each glyph's outline is turned into a path (`Outline::to_path_slanted`, scale `size / face units_per_em × px`, the face's slant) and filled antialiased with `Canvas::fill_path`, each rule as a rectangle; the colour is the item's own or `RenderOptions::colour`. The canvas is read back pixel by pixel as straight-alpha RGBA. PNG encoding is `quench_image::encode_png`.
* **SVG** (`src/typeset/svg.rs`): the same area in ems, padding in ems; one `<path>` per glyph with an outline, its points mapped to `((x + (px + slant·py)·k) / em, −(y + py·k) / em)`, quadratic segments with implied on-curve midpoints as TrueType draws them; one `<rect>` per rule. Numbers are rounded to four decimals with trailing zeros dropped. No `<defs>`/`<use>` sharing of repeated glyphs, no text elements: the SVG has no font dependency and no script, and renders the same everywhere (the tests render it back with [quench-svg](../quench-svg/index.md)).

## Performance and limits

* Nothing is cached by this crate. The math font's `MATH` table is parsed once per `Font` (by quench-text's `OnceLock`); the bundled fonts are parsed once per process. Each `typeset` builds its boxes again, and each `to_rgba`/`to_svg` parses glyph outlines again.
* The display list grows with the formula; an assembly repeats an extender at most 1000 times. Parsing is linear in the input apart from macro expansion, which is bounded as above.
* The reader allocates per token and per node; there is no arena. Formulas are short in practice; the fuzz tests run thousands of random formulas in well under a second in debug builds.
* Thread safety: all types are plain data; `Fonts` holds `Arc<Font>`, and `quench_text::Font` is `Sync`, so typesetting from several threads with one `Fonts` is fine.
