`quench-android` is the Rust side of the Android host's `native` plugin: a small framed-stdio protocol, an operation registry and two built-in operations. An app's native code is a separate program; the Kotlin host starts it, writes one request to its standard input and reads one answer from its standard output.

Version: **0.1.0**. Edition 2024 (workspace). No `unsafe`, no JNI, no loaded library.

The `Cargo.toml` description still says "a JNI entry point"; the code has none (see the gap report). The Kotlin half of the host (`WebView` app, bridge, plugins) is generated by `quench android init` and `quench plugin add`; see [quench-tool](../quench-tool/plugins.md).

## Install

```toml
[dependencies]
quench-android = { version = "0.1.0", registry = "ennor" }
```

`quench plugin add native` creates the `native/` crate with this dependency for you.

## Features

None.

## Dependencies

| Crate | Why |
|---|---|
| `quench-core` | `Date` and `Time` for the `tz.next` operation. |
| `quench-serde` | JSON (`Value`, `json::from_str`, `json::to_string`, `json!`) for `tz.next`. |
| `quench-tz` | `Zone` and `Resolved` to resolve a clock reading in a zone. |

Dev-dependency: `quench-test`. No other third-party crates.

## Minimal example

```rust
// native/src/main.rs
fn register_ops() {
    quench_android::register("heartbeat", |input| Ok(input.to_vec()));
}

fn main() -> std::process::ExitCode {
    quench_android::run(register_ops)
}
```

Standard output belongs to the protocol: log to standard error (`eprintln!`).
