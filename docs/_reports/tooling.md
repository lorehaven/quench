# Gap report: tooling crates

Crates: quench-args, quench-args-macros, quench-cli, quench-convert, quench-regex, quench-template, quench-schema, quench-test, quench-test-macros, quench-test-bdd, quench-test-bdd-macros. Guides: `docs/guides/testing.md`, `docs/guides/building-cli-tools.md`.

How things were verified: every Rust example in the new pages was compiled as a doctest in a scratch crate outside the repository (path dependencies on the crates, nothing in the repository was built or changed); filter, test, method, operator and statement outputs of quench-template, the messages of quench-schema and quench-convert, the mock server, the command runner, the BDD runner and the complete `notes` tool of the CLI guide were produced by running real code. Not verified: the Jekyll rendering of the site (only the Liquid escaping of the template pages was checked with the installed Liquid 4.0.4), anything that needs a real terminal (the pty test of quench-cli was not run; the REPL was driven through a pipe).

## 3. Open questions, suspected bugs and oddities (not fixed; file:line from the current sources)

1. **quench-args-macros silently ignores attributes on `Args` structs and `Subcommand` enums.** `attrs::command(&input.attrs)` is only called for `Parser` (`expand.rs`, `expand_struct`, `if is_parser`), and `expand_subcommand` never reads the enum's attributes. `#[derive(Args)] #[command(nope_at_all, about = "x")] struct G` compiles and does nothing (verified), which contradicts the "never a silent no-op" promise in `attrs.rs` and the crate docs. Doc comments on those items are ignored too.
2. **quench-template: `-2 ** 2` is `4`** (`syntax.rs`, `parse_power` parses a full unary expression as the base). Python and Jinja give `-4`.
3. **quench-template: wrong closer in the "missing" message.** An unterminated `{% if %}` reports ``missing `elif` `` and an unterminated `for` ``missing `else` `` (`syntax.rs`, `body`, `ends[0]`), with line 0 (so the message has no line).
4. **quench-template: integer literals are `i64` only** (`tokenize`): `18446744073709551615` is `bad number`, while arithmetic can produce `u64` values.
5. **quench-template: `escape`, `e`, `safe`, `forceescape` are no-ops** (`builtins.rs`). Documented; worth a note for anyone expecting HTML safety.
6. **quench-schema: an unresolvable or remote `$ref` is silently accepted** (`lib.rs` `check`: `if let Some(resolved) = resolve(..)`). A typo in a reference disables the check without an error; `Schema::new` does not verify that local references resolve. Reference cycles also end silently after 128 levels.
7. **quench-schema: `ErrorKind` for `propertyNames`** carries no detail (the inner kind is dropped).
8. **quench-regex: `find_at`/`captures_at`/`vm::search` panic** when `start > text.len()` or `start` is not on a character boundary (they slice `text[pos..]`); the rustdoc does not say so (documented in the new API page).
9. **quench-regex: per-match allocation.** `Searcher::next_slots` calls `vm::search`, which allocates two thread lists sized to the program for every match; a many-match iteration over a large program costs `matches x program size` allocations (`vm.rs` `search`, `Threads::new`).
10. **quench-regex: `escape` leaves spaces alone**, so `escape(text)` inside an `(?x)` pattern does not match spaces literally (`lib.rs` `escape`).
11. **quench-test-bdd: a misspelt *first* step is swallowed as scenario description.** `Scenario` parsing calls `description()` before the first step, which consumes every line that is not a keyword or a valid step word: `Scenario: S` / `Giben a total of 1` / `When I add 2` parses with **one** step (verified), while a misspelt later step is a parse error (`unexpected ...`). `gherkin.rs`, `Parser::description`. The scenario then fails or even passes with fewer steps than written.
12. **quench-test-bdd: regex steps are not anchored** (`expression.rs` `Matcher::new`, `raw` branch uses `captures`), so `regex = "x"` matches any step containing `x` and is often ambiguous. Documented; whether an automatic `^...$` was intended is unknown.
13. **quench-test-bdd: outline scenarios all report the line of the `Scenario Outline:`**, not of their `Examples` row (`runner.rs`, `location: format!("{place}:{}", expanded.line)`).
14. **quench-test: the output of tests is not captured** and `--nocapture` is accepted and ignored (`runner.rs`); parallel tests interleave their `println!` output.
15. **quench-test: the report title depends on `CARGO_PKG_NAME` read at run time** (`runner.rs`, `report_title`); running a test executable directly (outside `cargo test`) yields the title `tests · <binary>` and report files named `tests-<binary>`.
16. **quench-cli: `Keys::on_fd` starts a thread that reads the descriptor until it ends** and cannot be stopped; a program that stops using a `Keys` and reads the descriptor itself loses the next chunk (documented in the rustdoc; recorded here as a design limit). `edit_line` takes `history: &mut [String]` although it never writes to it. `visible_width` counts characters, so wide (CJK, emoji) text misplaces the cursor.
17. **quench-cli: `Tone` is not `Clone`/`Copy`/`PartialEq`** (kept by-value in `print_status` on purpose per a comment); `print_component_preview`, `print_error_line`, `print_inline` are not in `prelude`.
18. **quench-args: `-v=1` for a short *switch*** yields `unexpected argument '-=' found`, not "unexpected value" (`parse.rs`, `read_short_cluster`); untested. `ValueEnum` matching in the derive is case-sensitive; `ignore_case` exists only on the trait method and is never used by the derive. Help text is not wrapped.
19. **quench-convert: GGUF `scalar` has an arm for type 9 (array) that cannot be reached** (arrays are handled in `value`); `gguf::read` reads every element of a long array before discarding it, so a huge `max_array`-exceeding array is still read in full. CSV `Error::position()` is a line for quoting errors but a record number for `flexible = false`.
20. **Outside `docs/` and not touched:** the root `README.md` still links to the deleted flat pages (`./docs/quench-test.md`, `quench-test-bdd.md`, `quench-convert.md`, `quench-template.md`, `quench-args.md`, `quench-schema.md`, `quench-regex.md`, `quench-cli.md`); `quench-cli/README.md` was fixed. `docs/README.md` links were updated to `./crates/<crate>/index.md` for these crates; its ASCII tree (lines 11-20) still lists the old files.
