# Report: hosts and tool (quench-desktop, -native, -atspi, -wayland, quench-android, -surface, quench-tool)

Pages: `docs/crates/<crate>/` for the seven crates, `docs/guides/packaging.md`, `docs/guides/hosts.md`. Old flat pages deleted (all content covered or listed below); `docs/README.md` links repointed. Not run (by rule): any test that opens a window, any adb/device command, any signing, `quench build apk|aab|deb|rpm|arch|linux`, `quench android keystore`. Run and verified: `cargo build -p quench-tool`, `--help` of every subcommand, `quench doctor`, and in a scratch project `new`, `android init`, `plugin list/add/update`, `android launcher`, `linux init`, `build source`, error paths.

Public item counts (approximate; opcode constants and enum variants not counted separately): quench-android 7 items + 3 built-in operations (+ 1 unreachable `pub const`); quench-android-surface about 26; quench-desktop-wayland about 95 (+ about 100 opcode constants); quench-desktop-atspi about 56; quench-desktop-native 17; quench-desktop about 75 (including the plugins); quench-tool the library's about 120 plus the CLI (9 top-level commands, 14 leaf subcommands) and 11 Android plugins.

## 3. Open questions and suspected bugs

* `quench-android/Cargo.toml:6` says "a JNI entry point"; there is no JNI (the protocol is stdio frames). Description is stale.
* `quench-android/src/serve.rs` `pub const MAX_FRAME` is `pub` in a private module and not re-exported: unreachable from outside. Probably meant to be exported or private.
* `quench-android-surface/src/lib.rs`: `Surface::finished()` returns `exit`, which is initialised `false` and never set anywhere in the crate; the `Back` event writes `Out::Exit` instead. So `serve_with`'s `while !surface.finished()` only ends on input close. Either `exit` should be set when `Out::Exit` is sent or the field is dead.
* `quench-android/src/lib.rs` `builtins()` runs on every `call`; an app that registers `core.echo`/`core.version`/`tz.next` before the first `call` has its handler overwritten by the built-in. Probably unintended but harmless.
* `quench-desktop-wayland/src/window.rs` (line 365): the doc comment of `begin_frame` ("The frame to draw into: wait for the compositor...") is placed on `key_repeat`, merging two docs; `begin_frame` itself has none.
* `quench-desktop-wayland`: no `wl_output`, `xdg-decoration`, fractional scale or cursor shape; on a compositor that expects client-drawn decorations (GNOME) the window has no title bar (known limitation, listed in the protocol page).
* `quench-desktop/src/bridge.rs` `Bridge::handle`: a plugin that answers and then panics causes a second reply (`guard.reject("internal", ...)`) for the same id; the page ignores unknown ids, but the Android bridge ignores it by design (`Call.answered`).
* `quench-desktop/src/plugins/files.rs` vs `FilesPlugin.kt.tpl`: `pick_files` default for `multiple` is `false` on the desktop and `true` on Android (`optBoolean("multiple", true)`). Probably should agree.
* `quench-tool/templates/android/plugins/jobs/JobsPlugin.kt.tpl`: the `network` argument maps `"none"`, `"connected"`, `"unmetered"`; the default string is `"any"`, which falls to the `else` branch and means no network requirement (`NETWORK_TYPE_NONE`), i.e. the name `any` suggests "any network" but does not require one. A typed client that sends `"any"` explicitly gets no constraint. Probably a naming bug (`connected` is what requires a network).
* `quench-tool/src/system.rs`: `System::http` and `Http` (with `quench-client` `blocking`+`tls` features as dependencies) are not called by any command. Either planned for a publish step or dead weight in the dependency list.
* `quench-tool/src/dev.rs`: when interrupted (SIGINT) the process dies without killing the server or the desktop window child it spawned; only the test-only `Event::Stop` path kills them.
* `quench-tool/src/doctor.rs`: the label `node 22+ (browser tests)` does not check the version.
* `quench-tool/src/android.rs` `run`/`launch_dev`: `adb` is invoked without `-s`, so with several devices attached it relies on adb's default (`ANDROID_SERIAL`); fine for one device, ambiguous otherwise.
* `quench-tool/src/linux.rs` `deb`: the maintainer line is `<name> <noreply@example.com>` and Arch/RPM carry no dependency metadata (`Depends` is only in the `.deb`); the RPM/Arch packages are therefore not installable-checked for the webkit/gtk libraries.
* `quench-tool/templates/android/app/build.gradle.kts.tpl`: `release { isMinifyEnabled = false }` and signing only when `QUENCH_KEYSTORE` is set; `quench build apk --release` guards this, but `./gradlew assembleRelease` run by hand without it produces an unsigned APK.
* Unverified claims (marked *Unverified* in the pages or omitted): whether `.quench.toml` deserialization rejects unknown keys; that `quench-desktop` links `gtk-3` and `webkit2gtk-4.1` by name without headers (old claim); all measurements and coverage figures of the old pages; `Orca` behaviour; fcitx5/ibus behaviour; the desktop window tests.
* `README.md` (repository root, outside `docs/`) still links `./docs/quench-*.md` for these seven crates (lines 26-53); I did not edit it (outside `docs/`). The file tree in `docs/README.md` (lines 31-45) still lists the deleted files; only its link lines were repointed.
